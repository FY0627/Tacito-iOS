# 0029 iOS Swift 版：导入银行、钱包账单对账，读法全靠模板

- 状态：已采纳（`ios-swift/`）
- 日期：2026-11-23

## 背景

自动记账只能处理系统交给 App 的通知（[自动记账/README](../features/ios-swift-auto-bookkeeping/README.md)「限制」）：没触发的自动化、签名过期的那几天、
银行没发通知的交易都会漏。用户的朋友反映「老是漏账」，月底要一笔一笔对银行和钱包的账单。要一个「导入账单」：把这个月的账单都交给 App，
App 找出账本里没有的，补上。

开发者手上只有少数几份样本账单（几家内地和香港银行的流水 PDF、Excel，支付宝 CSV、微信 xlsx），银行和钱包太多，App 里一家一家写读法适配不完。
用户要求：

- App 里只放「导入规则（模板）」和「导入账单」的入口，不内置这几家的读法；模板由开发者用 skill 照着样本做好，发给用户自己导入；
- skill 的输出格式要严格控制；对账要准；
- 去重由 App 做；一次把要对账的账单都选进来，要密码的一起输密码；只有一个入口，各种文件格式都认。

[ADR 0028](0028-ios-swift-screenshot-templates.md) 讨论过「让用户用 AI Skill 做规则再导入」并没有选，因为要把短信、截图交给云端 AI，会用的用户也少。
这里不一样：用 skill 的是开发者，样本账单是用户给的；模板只有版式，没有任何人的数据，用户拿到的是做好的文件。

## 决定

**模板**（`BKModel/StatementTemplate.swift`，格式说明在 `.claude/skills/statement-template/FORMAT.md`）：一个 JSON 对象，写怎么认出账单、表头在哪、
每列是什么、日期写法、哪些行不记或记成什么、核对什么。

- 严格：自己读 JSON（分得清 `true` 和 `1`），每一层只认列出的键，必填的组合、正则、命名分组、日期写法都先查一遍，有一处不对整个文件不收，提示在哪一处。
- 存在新表 `statement_templates`（迁移 16），原样存 JSON；同一个 `id` 再导入换掉旧的。进备份，增量导入时这里有的不变。

**读账单**（`BKBackend/Statement/`）：

- 表格文件自己读：CSV（App 先按 UTF-8、GB18030 解码）、xlsx（zip 里 deflate 压缩的 XML，自己写的解压，一百多行）、老的 xls（OLE 复合文档里的 BIFF8）。
  Excel 的日期格子按样式换成「yyyy-MM-dd HH:mm:ss」。不用第三方库，Linux 上也能测。
- PDF、图片由 App 读字和位置（PDFKit、Vision，`Bookkeeping/App/StatementFileReader.swift`），交给 `StatementLayout` 排回表格：
  同一高度、字一样大的是一行；表头每格的左边到下一格的左边是一列；有金额的一行是一笔的锚，同一笔的其他行按模板的 `rows`（金额在第一行、最后一行、中间）
  归到锚上，离得超过两行高、字小三成、不在同一页的不归。斜着的字（水印）读的时候就丢掉。上了锁的 PDF 在 App 里输密码，不保存。
- 读完先核对：有余额列的，每笔之后的余额都要接得上（顺着、倒着都行，多币种分段）；账单上写了总笔数、收支合计的也要对上。
  核对没通过、有读不出的行的账单整份不用。

**对账**（`StatementImport.swift`）：几份账单一起：

1. 规则标成「不记」「账户里挪钱」的不记；
2. 钱包账单里用卡付的（付款方式写了尾号）算那张卡的；对方写了自己另一张卡的卡号的算转帐，推出另一边；
3. 几份账单里的同一笔（同账户、同方向、同金额币种、前后 3 天，每份账单最多一笔，两份钱包账单的不合）合成一笔，商户、时间用钱包写的；
   一样近的按对方的字重合得多的配（银行账单上的「*明」对支付宝的「王明」）；
4. 只知道一边的转帐（支付宝提现没写到哪张卡）：另一个账户上同金额、前后 2 天只有一笔（或同一天几笔对几笔）时配成一对；
5. 和账本里已入账的流水比：同账户、同方向、同金额（或外币原币、实扣一样）、前后 3 天，一笔只对一笔。

账本里没有的是「漏记」，默认全选，点一下补记（来源 `statement`，转帐两边都补时配成一对，补完照常自动归类）；也列出「已经记了」
「账本里有、账单上没有」（账单覆盖的账户和日期里没对上的流水，给用户查错记）和用没添加的卡付的。补记的流水记着这次导入的编号，可以撤销这一次。
账单是哪个账户的按卡号、银行、钱包自动认，认不出时用户选一次，按「模板 + 账单上的号码」记住。

**入口**：「我的 › 数据 › 导入账单」，只有这一个。可以一次选几份账单和模板文件，模板先装，之前认不出的账单再认一次；要密码的一起列出来输。
里面有「账单模板」列表（左滑删除）。不放说明文字。

**做模板**：skill `.claude/skills/statement-template`，试读用 BKCore 里的命令行 `StatementCheck`（和 App 同一套代码，在 Docker 里跑），
PDF 先用 skill 的 `extract_pdf.py` 照 App 的方式读成字和位置。核对通过才交付。样本账单、读出来的东西不进仓库。

## 没有选的

- **App 里内置这几家的读法**：用户不要；适配不完，改版要发新版本。
- **App 里让用户自己点出表格做模板**（像截图模板那样）：账单一页几十笔、几列，手机上点不清；做错了没有核对很难发现。以后可以在这个格式上加。
- **App 里调用大模型认账单**：要把账单交给云端，和本地优先不合。
- **只按金额、日期猜重复，直接导入**：会把两笔一样的消费当成一笔或者重复记。这里一笔只对一笔，同一份账单里的两笔不会合，结果给用户看过再补。
- **第三方的 xlsx、xls、PDF 库**：要另写依赖、增加体积；需要的部分自己写，和测试一起不大。

## 影响

- 模板格式改了要同时改 `StatementTemplate.swift`、FORMAT.md、`StatementTests`，并重新试读手上的模板；只加不减，老模板要还能读。
- PDF 在手机上（PDFKit）和电脑上（PyMuPDF）读出的字的切法、位置可能不完全一样，模板交付后要在真机上用同一份账单试一次。截图（Vision）只能在真机上试。
- 账单的表头不在每页重复的 PDF 现在读不了；遇到再加。
